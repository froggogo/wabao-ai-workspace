## 一、OpenAI API 能力全景

在设计产品前，先系统梳理 OpenAI Platform 提供的核心能力（来源：官方文档），并标注每项能力可支撑的产品功能方向。

### 1.1 核心接口层

| 能力 | 说明 | 可实现的功能 |
| --- | --- | --- |
| **Responses API** | 统一的模型请求接口，支持文本、结构化输出、工具调用、多模态输入 | 对话、问答、内容生成、结构化抽取 |
| **Agents SDK** | 代码优先的智能体框架，支持工具编排、任务交接（handoff）、审批、追踪、沙箱执行 | 多步任务自动化、工作流机器人 |
| **Conversation state** | 会话状态管理 | 多轮对话、上下文记忆 |
| **Streaming / WebSocket** | 流式输出、低延迟双向通信 | 打字机式回复、实时语音 |
| **Background mode** | 后台长任务模式 | 深度研究、批量生成 |
| **Webhooks** | 事件回调 | 异步任务完成通知 |

### 1.2 模型层（GPT-5.6 系列）

| 模型 | 定位 | 适用场景 |
| --- | --- | --- |
| **GPT-5.6 Sol** | 旗舰推理模型，复杂专业工作 | 复杂推理、编程、深度分析 |
| **GPT-5.6 Terra** | 智能与成本平衡 | 通用对话、日常任务 |
| **GPT-5.6 Luna** | 成本优化，高并发 | 大批量、成本敏感场景 |

### 1.3 文本与推理

- **文本生成 / 代码生成**：内容创作、代码补全与生成
- **结构化输出（Structured Output）**：按 JSON Schema 返回，用于表单填充、数据抽取
- **推理模型（Reasoning）**：`reasoning_effort` 可调，处理复杂多步任务

### 1.4 多模态

| 能力 | 功能方向 |
| --- | --- |
| **Images and vision** | 图像理解、看图问答、图片内容分析 |
| **Image generation（GPT Image 2）** | AI 生图、海报/配图生成 |
| **Video generation** | AI 视频生成 |

### 1.5 语音与实时

- **Realtime API**（WebRTC / WebSocket / SIP）：实时语音对话、语音智能体
- **Speech to text**：语音转写、会议记录
- **Speech generation（TTS）**：文本转语音、播报
- **Live translation**：实时翻译

### 1.6 搜索与检索

- **Web search**：联网搜索获取实时信息
- **File search**：文件检索
- **Retrieval / Embeddings**：向量化 + 语义检索，构建 RAG 知识库
- **Deep research**：深度研究，自动生成研究报告

### 1.7 工具与连接

- **Function calling**：让模型调用自定义函数
- **MCP and Connectors**：接入外部数据源与工具
- **Tool search / Programmatic tool calling / Skills**：工具管理与技能封装
- **Computer use / Shell / Code interpreter**：操作计算机、执行代码

### 1.8 安全、优化与运营

| 能力 | 用途 |
| --- | --- |
| **Moderation** | 内容审核，过滤违规内容 |
| **Prompt caching** | 提示缓存，降低成本与延迟 |
| **Batch** | 批量处理，成本优化 |
| **Flex / Priority processing** | 弹性 / 优先级处理 |
| **Evals** | 效果评估与回归测试 |
| **Fine-tuning** | 微调定制模型（SFT、DPO、RFT、视觉微调） |
| **Rate limits / Admin APIs / Error codes** | 限流、管理、错误处理 |

## 二、产品概述

> **【定位已评审确定 · 2026-07-21】** 产品聚焦 **多模态**，采用「**文本 → 图像 → 语音**」分阶段落地路径：先把文本对话/创作做扎实，再叠加图像理解与生成，最后接入语音与实时交互，最终形成"文、图、声统一的多模态 AI 工作台"。

### 2.1 产品定位

**蛙宝 AI 工作台**是一款以**多模态**为核心的 AI 生产力平台——在同一个对话式工作空间里，用文字、图片、语音自由地输入与创作，让"文、图、声"在一次交互中自然流转。

它不是又一个纯文字聊天工具，而是把**文本、图像、语音三种模态融为一体**的统一入口：你可以说一段话、贴一张图、写一段字，AI 都能理解并以任意模态回应。

一句话概括：**文、图、声一体的多模态 AI 工作台。**

**核心定位三要素**：
- **主攻能力**：多模态（文本 + 图像 + 语音）统一交互。
- **落地节奏**：文本先行 → 图像其次 → 语音最后，逐阶段验证价值。
- **记忆点**：一个入口，三种模态无缝切换，输入输出皆可跨模态。

### 2.2 目标用户

以内容与知识密集型的工作者为主，他们的工作天然涉及多种媒介（文案 + 配图 + 语音/会议）。

| 用户类型 | 典型画像 | 多模态诉求 |
| --- | --- | --- |
| 内容/营销从业者 | 运营、新媒体、市场 | 文案 + 配图一站式产出 |
| 个人知识工作者 | 产品、咨询、设计 | 图文理解、看图问答、语音速记 |
| 中小团队 | 5–200 人的公司/部门 | 共享的多模态创作与协作空间 |
| 客服/会议场景 | 需要语音转写与实时交互 | 语音输入、实时对话、会议纪要 |

### 2.3 核心价值

1. **多模态统一**：文字、图片、语音在同一对话中自由输入与输出，无需在多个工具间切换。
2. **跨模态流转**：图生文、文生图、语音转文、文转语音，一句话完成媒介转换。
3. **渐进可用**：文本能力先上线即可用，图像、语音分阶段增强，用户体验持续升级。
4. **可控**：多模态内容统一审核，成本与用量可视。

### 2.4 差异化

- 相比纯聊天工具：**原生多模态**，不是附加的插件，而是文/图/声一体的核心体验。
- 相比单点工具（只生图 / 只转写）：**统一工作空间**，多种模态在一次任务里协同。
- 相比大而全平台：**聚焦多模态这一条主线**打透，节奏清晰、体验连贯。

## 三、模块划分总览

> 模块按多模态落地阶段推进：**P1 文本 → P2 图像 → P3 语音 → P4 深化**。下方括号内标注了所属阶段。

```
蛙宝 AI 工作台（多模态主线：文 → 图 → 声）
├── M1  智能对话与问答      （Responses API / 流式 / 会话状态）      [P1 文本]
├── M3  内容创作工作室      （文本生成 / 结构化输出 / 模板）        [P1 文本]
├── M9  安全与合规          （Moderation / 审计 / 数据治理）        [P1 文本]
├── M12 账户与计费          （订阅 / 用量 / 配额）                  [P1 文本]
├── M5  图像与多模态        （Vision / Image Gen / Video Gen）      [P2 图像]
├── M2  知识库与 RAG        （Embeddings / File search / 图文检索） [P2 图像]
├── M10 模型与成本管理      （模型路由 / Prompt caching / Batch）   [P2 图像]
├── M4  语音与实时交互      （Realtime / STT / TTS / 翻译）         [P3 语音]
├── M8  团队协作与工作空间  （多租户 / 权限 / 共享）                [P3 语音]
├── M11 效果评估与运营      （Evals / 分析看板 / 反馈闭环）         [P3 语音]
├── M6  智能体与工作流      （Agents SDK / 编排 / 审批 / 追踪）     [P4 深化]
└── M7  工具与集成中心      （Function calling / MCP / Connectors） [P4 深化]
```

> 说明：三种模态是主线，M1/M3（文）、M5（图）、M4（声）为各阶段的**核心模态模块**；其余为对应阶段的**支撑模块**。

## 四、模块详细设计

> 每个模块包含：功能描述、关键用户故事、依赖的 OpenAI API、交互流程、核心数据模型、边界与注意事项。

### M1 智能对话与问答

**功能描述**：产品的核心入口，提供多轮对话、流式回复、上下文记忆、可切换模型与人设。支持在对话中直接调用知识库、工具、生图等能力。

**关键用户故事**：
- 作为用户，我可以像聊天一样提问，得到打字机式的流式回答。
- 作为用户，我可以在对话中切换模型（Sol/Terra/Luna）以平衡质量与成本。
- 作为用户，我可以创建带特定人设（system prompt）的助手。
- 作为用户，历史对话可保存、检索、继续。

**依赖 API**：`Responses API`、`Streaming`、`Conversation state`、`Reasoning`（`reasoning_effort`）。

**交互流程**：
```
用户输入 → 前端 SSE 连接 → 后端组装 messages（含系统提示/记忆/检索片段）
→ 调用 Responses API（stream=true）→ 流式回传 token → 前端逐字渲染
→ 若触发工具/知识库 → 走 M2/M7 → 结果回填对话
```

**核心数据模型**：
- `Conversation`：id、user_id、workspace_id、title、model、system_prompt、created_at
- `Message`：id、conversation_id、role(user/assistant/tool)、content、tokens、cost、created_at

**边界与注意**：
- 上下文超长时需做**摘要压缩**（Compaction）。
- 敏感输入先过 M9 审核。
- 记录每条消息 token/成本用于 M10/M12。

---

### M2 知识库与 RAG

**功能描述**：用户上传文档（PDF、Word、网页、表格等），系统切分、向量化、入库，实现基于私有知识的问答与引用溯源。

**关键用户故事**：
- 作为用户，我可以上传公司资料，AI 回答时基于这些资料并给出出处。
- 作为团队，我可以创建多个知识库并分配访问权限。
- 作为用户，我能看到答案引用了哪些原文片段。

**依赖 API**：`Embeddings`、`File search`、`Retrieval`、`File inputs`、（可选）`Deep research`。

**交互流程**：
```
上传文档 → 解析/清洗 → 分块(chunking) → Embeddings 向量化 → 存入向量库
提问 → 问题向量化 → 语义检索 Top-K 片段 → 拼入 prompt → Responses API 生成
→ 返回答案 + 引用来源（citation）
```

**核心数据模型**：
- `KnowledgeBase`：id、workspace_id、name、visibility
- `Document`：id、kb_id、name、type、status、source_url
- `Chunk`：id、doc_id、text、embedding(vector)、metadata

**边界与注意**：
- 分块策略影响召回质量（按语义/固定长度 + overlap）。
- 引用溯源必须可点击定位原文。
- 大文件走后台异步处理 + Webhook 通知完成。

---

### M3 内容创作工作室

**功能描述**：面向写作/办公的结构化创作场景，提供模板（周报、营销文案、邮件、PRD、代码等）、大纲生成、续写、润色、多语言翻译，支持结构化输出直接填充表单。

**关键用户故事**：
- 作为运营，我选择"小红书文案"模板，填几个关键词即可生成多版本文案。
- 作为产品，我可以让 AI 按固定 JSON 结构输出需求点，直接导入项目工具。
- 作为用户，我可以选中一段文字进行"润色/扩写/缩写/翻译"。

**依赖 API**：`Text generation`、`Structured Output（JSON Schema）`、`Code generation`。

**交互流程**：
```
选择模板 → 填写变量 → 后端套用 prompt 模板 + Schema
→ Responses API（可指定 response_format=json_schema）→ 渲染结果/表单
→ 用户编辑/重生成/导出（Markdown/Docx/复制）
```

**核心数据模型**：
- `Template`：id、name、category、prompt、input_schema、output_schema
- `Creation`：id、user_id、template_id、inputs、output、created_at

**边界与注意**：
- 模板可由运营在后台配置，无需发版。
- 结构化输出需校验 Schema，失败自动重试。

---

### M4 语音与实时交互

**功能描述**：支持语音输入/输出的实时对话、会议/录音转写、文本朗读、实时翻译，构建"能说话的助手"。

**关键用户故事**：
- 作为用户，我可以按住说话，AI 实时语音回复（低延迟）。
- 作为用户，我可以上传会议录音，得到转写文本 + 摘要 + 待办。
- 作为用户，AI 的回答可以朗读出来。

**依赖 API**：`Realtime API`（WebRTC/WebSocket）、`Speech to text`、`Speech generation(TTS)`、`Live translation`。

**交互流程**：
```
实时语音：麦克风 → WebRTC/WS → Realtime API → 语音/文本流 → 前端播放
转写：上传音频 → STT → 文本 → （可选）摘要/提取待办（M1/M3）
朗读：文本 → TTS → 音频播放
```

**核心数据模型**：
- `VoiceSession`：id、user_id、mode(realtime/transcribe)、duration、created_at
- `Transcript`：id、session_id、text、segments、summary

**边界与注意**：
- 实时链路需处理网络抖动、打断（barge-in）。
- 转写长音频建议分段 + 后台任务。

---

### M5 图像与多模态

**功能描述**：图像理解（看图问答/OCR/分析）、AI 生图（配图、海报、Logo 草稿）、可扩展视频生成。

**关键用户故事**：
- 作为用户，我上传一张图表，AI 帮我解读数据。
- 作为运营，我输入描述生成营销配图，可指定尺寸/风格。
- 作为用户，我可以对生成的图进行局部重绘/变体。

**依赖 API**：`Images and vision`、`Image generation（GPT Image 2）`、`Video generation`。

**交互流程**：
```
理解：上传图片 → Responses API（多模态输入）→ 分析结果
生成：输入 prompt + 参数(尺寸/风格/数量) → Image Gen → 返回图片 → 保存/下载
```

**核心数据模型**：
- `MediaAsset`：id、user_id、type(image/video)、url、prompt、meta、created_at

**边界与注意**：
- 生成内容需过 M9 审核。
- 存储用对象存储（如 S3），仅存引用。

---

### M6 智能体与工作流

**功能描述**：产品的"高级形态"。用户/管理员可编排智能体：给定目标，智能体自动规划、调用工具、检索知识、分步执行，支持人工审批节点与执行追踪。

**关键用户故事**：
- 作为运营，我配置"竞品调研"智能体：联网搜索 → 汇总 → 生成报告 → 发邮件。
- 作为管理员，敏感操作（如发送对外邮件）需人工审批后才执行。
- 作为用户，我能看到智能体每一步的思考与工具调用记录（可追踪）。

**依赖 API**：`Agents SDK`（编排、handoff、审批、tracing）、`Background mode`、`Web search`、`Code interpreter`、结合 M2/M7。

**交互流程**：
```
定义目标 & 工具集 → Agent 规划步骤 → 逐步执行(调用工具/检索/生成)
→ 遇审批节点暂停 → 人工确认 → 继续 → 输出结果 + 执行轨迹(trace)
```

**核心数据模型**：
- `Agent`：id、name、goal、tools[]、model、guardrails
- `AgentRun`：id、agent_id、status、steps[]、trace、result、created_at

**边界与注意**：
- 必须有 **guardrails**（工具白名单、最大步数、超时、成本上限）。
- 高风险动作强制人工审批。
- 长任务用后台模式 + Webhook。

---

### M7 工具与集成中心

**功能描述**：管理可被对话/智能体调用的工具与外部连接（Function calling 自定义函数、MCP/Connectors 接入第三方系统，如日历、CRM、数据库、内部 API）。

**关键用户故事**：
- 作为管理员，我注册一个"查询订单"函数，用户在对话里问订单即可自动调用。
- 作为团队，我通过 MCP 接入内部知识系统/工单系统。
- 作为用户，AI 能帮我"在日历里新建会议"。

**依赖 API**：`Function calling`、`MCP and Connectors`、`Tool search`、`Skills`。

**交互流程**：
```
注册工具(定义 name/参数 schema/端点) → 模型判断需调用 → 返回工具调用请求
→ 后端执行(带鉴权) → 结果回传模型 → 生成最终回答
```

**核心数据模型**：
- `Tool`：id、workspace_id、name、type(function/mcp)、schema、endpoint、auth、enabled
- `ToolCallLog`：id、tool_id、input、output、status、latency

**边界与注意**：
- 工具鉴权与最小权限原则。
- 记录所有调用用于审计（M9）与排障。
- 外部调用需超时与重试策略。

---

### M8 团队协作与工作空间

**功能描述**：多租户工作空间，支持成员管理、角色权限、资源共享（会话/知识库/模板/智能体）、协作评论。

**关键用户故事**：
- 作为管理员，我邀请成员并分配角色（Owner/Admin/Member/Viewer）。
- 作为团队，我们共享一个知识库和一套智能体。
- 作为成员，我能把一个对话分享给同事继续。

**依赖 API**：不直接依赖（业务层），但所有资源需带 `workspace_id` 隔离。

**核心数据模型**：
- `Workspace`：id、name、plan、owner_id
- `Membership`：workspace_id、user_id、role
- `ShareLink`：resource_type、resource_id、scope、expires_at

**边界与注意**：
- 严格数据隔离，所有查询按 workspace 过滤。
- 权限校验在 API 网关统一处理。

---

### M9 安全与合规

**功能描述**：内容审核、数据治理、审计日志、隐私保护，保证平台合规可控。

**关键用户故事**：
- 作为平台，用户输入与 AI 输出的违规内容被自动拦截。
- 作为管理员，我能查看所有 AI 调用的审计日志。
- 作为企业，我能设置数据不用于训练、可导出/删除。

**依赖 API**：`Moderation`、`Permissions`、`Your data`（数据控制）。

**交互流程**：
```
输入 → Moderation 检查 → 通过则继续/拦截并提示
输出 → Moderation 检查 → 通过则展示/过滤
所有调用 → 写审计日志
```

**核心数据模型**：
- `AuditLog`：id、workspace_id、user_id、action、resource、meta、created_at
- `ModerationRecord`：id、content_ref、flagged、categories、score

**边界与注意**：
- 审核策略可分级（拦截/警告/放行）。
- 遵循数据留存与删除合规要求（GDPR 等）。

---

### M10 模型与成本管理

**功能描述**：模型路由（按任务/成本自动选模型）、Prompt 缓存、批处理、用量与成本监控，帮助控制 API 花费。

**关键用户故事**：
- 作为平台，简单任务自动用 Luna，复杂任务用 Sol，降低成本。
- 作为平台，重复的系统提示走缓存，减少重复计费。
- 作为管理员，我能看到各模型/各功能的成本占比。

**依赖 API**：`Prompt caching`、`Batch`、`Flex/Priority processing`、`Rate limits`、`Admin APIs`。

**核心数据模型**：
- `UsageRecord`：id、workspace_id、feature、model、input_tokens、output_tokens、cost、cached
- `RoutingRule`：condition、target_model

**边界与注意**：
- 路由规则可配置，兜底为 Terra。
- 触发限流时排队/降级并提示用户。

---

### M11 效果评估与运营

**功能描述**：内置评估集与回归测试、用户反馈（点赞/点踩）、数据看板，形成"生成—反馈—优化"闭环。

**关键用户故事**：
- 作为算法/产品，我用 Evals 对比不同 prompt/模型的效果。
- 作为用户，我能对回答点赞/点踩并补充说明。
- 作为运营，我能看到活跃、留存、热门功能等指标。

**依赖 API**：`Evals`、（优化模型时）`Fine-tuning`。

**核心数据模型**：
- `EvalSet` / `EvalRun`：数据集与评测结果
- `Feedback`：message_id、rating、comment
- 运营指标：DAU/MAU、会话数、成本、满意度

**边界与注意**：
- 反馈数据可反哺 prompt 优化与微调。
- 上线前用 Evals 做回归，防止 prompt 改动导致退化。

---

### M12 账户与计费

**功能描述**：注册登录、订阅套餐、用量配额、按量计费、发票。

**关键用户故事**：
- 作为用户，我可以选择免费/专业/团队套餐。
- 作为管理员，超出配额时收到提醒并可升级。
- 作为财务，我可以下载账单。

**依赖 API**：结合 M10 用量数据；计费由自有系统 + 第三方支付（如 Stripe）。

**核心数据模型**：
- `Subscription`：workspace_id、plan、quota、period
- `Invoice`：id、amount、items、status

**边界与注意**：
- 用量实时计量，接近配额时预警。
- 免费额度与限流联动，防滥用。

## 五、技术架构

### 5.1 总体分层

```
┌─────────────────────────────────────────────┐
│  客户端：Web / 桌面 / 移动 / 浏览器插件         │
├─────────────────────────────────────────────┤
│  API 网关：鉴权 / 限流 / 路由 / 审计           │
├─────────────────────────────────────────────┤
│  应用服务层                                     │
│   对话服务 · 知识库服务 · 创作服务 · 语音服务   │
│   智能体服务 · 工具服务 · 计费服务              │
├─────────────────────────────────────────────┤
│  AI 编排层（核心）                              │
│   Prompt 管理 · 模型路由 · RAG 检索 · 工具调度  │
│   审核 · 缓存 · 成本计量                        │
├─────────────────────────────────────────────┤
│  OpenAI Platform（Responses / Agents / ...）    │
├─────────────────────────────────────────────┤
│  数据层：关系库 · 向量库 · 对象存储 · 缓存 · 队列 │
└─────────────────────────────────────────────┘
```

### 5.2 关键技术选型建议

| 层 | 建议方案 |
| --- | --- |
| 前端 | React / Next.js + SSE/WebSocket |
| 后端 | Node.js（NestJS）或 Python（FastAPI） |
| SDK | OpenAI 官方 SDK（Node/Python） |
| 向量库 | pgvector / Milvus / Qdrant |
| 关系库 | PostgreSQL |
| 缓存/队列 | Redis / 消息队列（长任务） |
| 对象存储 | S3 兼容存储 |
| 实时语音 | WebRTC + Realtime API |
| 可观测 | 日志 + Tracing + 成本看板 |

### 5.3 AI 编排层职责（重点）

这是产品的核心竞争力所在：
- **Prompt 中心化管理**：模板、版本、变量。
- **模型路由**：按任务复杂度/成本选择 Sol/Terra/Luna。
- **RAG 管道**：检索 → 重排 → 拼接 → 生成 → 溯源。
- **工具调度**：Function calling / MCP 统一执行与鉴权。
- **安全网关**：输入输出审核。
- **成本与缓存**：Prompt caching、用量计量。

## 七、里程碑与路线图

> **路线图主线：多模态分阶段落地（文本 → 图像 → 语音）。** 每一阶段都是一个可独立上线、可验证价值的完整体验，后一模态叠加在前一模态之上，而非推倒重来。

### 7.1 分阶段路线（按模态推进）

| 阶段 | 模态重点 | 目标 | 主要模块 |
| --- | --- | --- | --- |
| **P1 文本（1–2 月）** | 📝 纯文本 | 打透文本对话与创作，跑通核心闭环（👉 [P1 原型与接口设计](./2026-07-21-16_15-P1-文本阶段-原型与接口设计.md)） | M1 对话、M3 创作、M9 基础审核、M12 基础账户 |
| **P2 图像（3–4 月）** | 🖼️ 文 + 图 | 叠加图像理解与生成，实现图文互转 | M5 图像与多模态（Vision + Image Gen）、M2 知识库（图文）、M10 成本管理 |
| **P3 语音（5–6 月）** | 🔊 文 + 图 + 声 | 接入语音与实时交互，形成三模态一体 | M4 语音（STT/TTS/Realtime）、M8 协作、M11 评估运营 |
| **P4 深化（持续）** | 全模态增强 | 自动化、集成与定制 | M6 智能体、M7 工具集成、视频生成、微调 |

### 7.2 各阶段关键交付物

- **P1 文本**：多轮流式对话、模型切换、人设助手、内容创作模板、结构化输出、历史管理。
- **P2 图像**：看图问答/OCR/图表解读、文生图（配图/海报）、图片局部重绘与变体、"图 → 文案"一键生成。
- **P3 语音**：按住说话实时语音对话、音频/会议转写 + 摘要 + 待办、AI 回答朗读（TTS）、实时翻译。
- **P4 深化**：多模态智能体（如"读图 → 检索 → 生成图文报告 → 语音播报"）、外部工具集成、视频生成。

## 八、成本模型与风险

### 8.1 成本构成
- **模型调用费**（占大头，按 token）：靠模型路由 + Prompt caching + Batch 优化。
- **Embeddings/存储费**：知识库规模相关。
- **语音/图像/视频**：按时长/张数计费。
- **基础设施**：服务器、向量库、存储。

### 8.2 主要风险与对策

| 风险 | 对策 |
| --- | --- |
| API 成本失控 | 模型路由、缓存、配额、成本看板 |
| 依赖单一供应商 | 编排层抽象，预留多模型适配 |
| 内容合规风险 | Moderation + 人工审核 + 审计 |
| 幻觉/不准确 | RAG 溯源 + Evals + 反馈闭环 |
| 数据安全 | 加密、隔离、权限、合规删除 |
| 限流/稳定性 | 重试、降级、队列、兜底 |
