## 一、设计目标与范围

### 1.1 P1 目标

打透**纯文本**的核心闭环：用户可注册登录 → 进入工作台 → 与 AI 多轮流式对话 → 使用模板进行内容创作 → 结果可编辑/导出，全程内容经过审核，用量被计量。

### 1.2 P1 功能清单（In Scope）

| 模块 | 功能 |
| --- | --- |
| M12 账户与会员 | 注册、登录、登出、Token 刷新、个人信息、用量查看、**会员套餐与升级** |
| M1 对话 | 会话增删改查、多轮流式对话、模型切换、人设助手、消息重生成、停止生成 |
| M3 创作 | 模板列表、模板创作（含结构化输出）、创作历史、导出 |
| M9 审核 | 输入/输出内容审核（后端内嵌，非独立页面） |

### 1.3 不在本阶段（Out of Scope）

图像、语音、知识库 RAG、智能体、团队协作、外部工具集成（分别属于 P2/P3/P4）。

## 四、关键交互流程

### 4.1 流式对话（核心）

```
用户输入消息
  → 前端 POST /conversations/:id/messages (stream=true, SSE)
  → 后端：① 输入审核(Moderation) 不通过则返回 error 事件
          ② 组装上下文(system_prompt + 历史 + 本条)
          ③ 调 OpenAI Responses API (stream)
  → SSE 逐块下发 delta 事件 → 前端逐字渲染
  → 结束下发 done 事件(含 usage/message_id)
  → 后端：输出审核 + 落库 + 计量
用户可中途点“停止” → 前端中断 SSE / 调 POST /messages/:id/stop
```

**SSE 事件类型**：
- `message.start`：返回 assistant message_id
- `message.delta`：`{ "text": "增量文本" }`
- `message.done`：`{ "finish_reason", "usage": {...} }`
- `error`：`{ "code", "message" }`（如审核拦截、限流）

### 4.2 模板创作流程

```
选择模板 → GET /templates/:id 取 input_schema
→ 动态渲染表单 → 用户填写 → POST /creations (stream 可选)
→ 后端套 prompt 模板；若模板含 output_schema 则用 Structured Output
→ 流式/一次性返回结果 → 前端渲染 → 用户编辑/重生成/导出
```

### 4.3 认证流程

```
注册 POST /auth/register → 返回 access_token + refresh_token
登录 POST /auth/login    → 返回 access_token(短) + refresh_token(长)
访问受保护接口：Header Authorization: Bearer <access_token>
过期 → POST /auth/refresh 换新 access_token
登出 POST /auth/logout   → 失效 refresh_token
```

### 4.4 会员升级流程（M12）

```
用户在 /app/pricing 或用量页点「升级」
  → 选择套餐 + 计费周期（月/年）→ 确认弹窗展示价格
  → POST /billing/subscriptions { plan, cycle }
  → 后端创建订单 → 跳转支付（微信/支付宝/Stripe）
  → 支付成功 Webhook → 更新 Subscription（plan/quota/period）
  → 前端刷新 /users/me 与 /usage → 套餐与配额即时生效
降级/取消：期末生效，不影响当前计费周期已购权益。
```

> 落地状态（已实现）：后端 `GET /plans`、`GET /billing/subscription`、`POST /billing/subscriptions` 已上线；升级即时生效并**持久化**（更新 `User.plan` 与 `quota_tokens`），暂不接支付；企业版返回 400 引导联系销售。套餐权益中的**模型白名单已强制**（如免费版调用 Sol 返回 403）。配置集中在 `apps/api/src/modules/billing/plans.ts`。

## 五、接口设计

### 5.0 通用约定

- **Base URL**：`/api/v1`
- **认证**：除 `/auth/*` 外，均需 `Authorization: Bearer <access_token>`。
- **格式**：请求/响应均为 `application/json`（流式为 `text/event-stream`）。
- **成功响应**：`{ "data": {...} }`；**错误响应**：`{ "error": { "code", "message", "details?" } }`。
- **分页**：`?page=1&page_size=20`，返回 `{ "data": [...], "pagination": { "page", "page_size", "total" } }`。
- **幂等**：写操作可带 `Idempotency-Key` 头。

| POST | `/messages/:id/feedback` | 点赞/点踩 |

**POST /conversations/:id/messages（流式）**
```
Request Header: Accept: text/event-stream
Body: { "content": "帮我写一段周报", "stream": true, "model": "gpt-5.6-terra" }

Response: text/event-stream
event: message.start
data: {"message_id":"msg_9","role":"assistant"}

event: message.delta
data: {"text":"本"}

event: message.delta
data: {"text":"周"}

event: message.done
data: {"finish_reason":"stop","usage":{"input_tokens":30,"output_tokens":180}}
```

**非流式**（`stream=false`）直接返回：
```json
{ "data": { "message": { "id": "msg_9", "role": "assistant",
  "content": "…", "usage": {...} } } }
```

**审核拦截时**（流式内以 error 事件；非流式返回 4xx）：
```
event: error
data: {"code":"content_flagged","message":"内容不符合规范","details":{"categories":["violence"]}}
```

### 5.6 审核（M9 · 内部）

审核为**后端内嵌能力**，不暴露独立业务页面。所有对话/创作在调用模型前后自动执行：
- 调 OpenAI `Moderation` 检查输入与输出。
- 命中策略：`block`（拦截并返回 `content_flagged`）/ `warn`（放行并记录）。
- 记录 `ModerationRecord` 供审计。

（可选）管理端只读接口：`GET /admin/moderation-records`。

## 七、错误码与通用约定

| HTTP | code | 说明 |
| --- | --- | --- |
| 400 | `invalid_request` | 参数校验失败 |
| 401 | `unauthorized` | 未登录 / token 失效 |
| 403 | `forbidden` | 无权限访问该资源 |
| 404 | `not_found` | 资源不存在 |
| 409 | `conflict` | 冲突（如邮箱已注册） |
| 422 | `content_flagged` | 内容被审核拦截 |
| 429 | `rate_limited` | 触发限流 / 超出配额 |
| 500 | `internal_error` | 服务内部错误 |
| 502 | `upstream_error` | OpenAI 上游异常（需重试/降级） |

**限流/配额**：超配额返回 429 + `details.quota`；接近配额时在 `/usage` 与响应头 `X-Quota-Remaining` 提示。

**上游降级**：OpenAI 异常时按 `Sol→Terra→Luna` 或重试，仍失败则返回 502 并提示用户。

## 八、验收标准

P1 验收（Definition of Done）：

- [ ] 用户可完成注册/登录/登出，token 刷新正常。
- [ ] 可创建/切换/重命名/删除会话，历史持久化。
- [ ] 对话支持流式输出、停止生成、重生成、复制、点赞点踩。
- [ ] 可切换模型与选择助手人设，影响实际回复。
- [ ] 创作工作室：模板库浏览、动态表单、流式生成、导出、历史。
- [ ] 结构化模板可返回并渲染 JSON 结果。
- [ ] 所有输入输出经过审核，违规被拦截并提示。
- [ ] 用量被正确计量并在设置页展示，接近/超配额有提示。
- [ ] 会员定价页可对比套餐权益、切换月/年计费、发起升级并即时生效（原型为模拟）。
- [ ] 统一错误码，上游异常有降级与友好提示。
- [ ] 首 token 延迟 < 2s，流式渲染流畅。
