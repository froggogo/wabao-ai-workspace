## 一、设计目标与范围

### 1.1 P2 目标

在 P1 文本闭环之上**叠加图像模态**，实现"文 → 图"与"图 → 文"的双向流转：用户既能用文字生成图片（AI 绘图），也能上传图片让 AI 解读（看图问答），全程沿用 P1 已建立的审核、计量、套餐权益体系。

### 1.2 P2 功能清单（In Scope）

| 模块 | 功能 |
| --- | --- |
| M5 图像生成 | 文生图（模型 / 比例 / 风格 / 批量张数）、流式逐张上屏、变体重绘 |
| M5 图像管理 | 作品画廊（筛选 / 搜索）、大图预览、下载、删除 |
| M5 图像理解 | 对话内上传图片提问（Vision 看图问答），消息含图落库可回看 |
| M5 × M3 图 → 文案 | 依据图片一键生成小红书笔记 / 营销文案 / 电商详情 / 社交短文 / 无障碍描述，结果并入创作历史 |
| M9 审核 | 绘图 prompt、模型改写后的 prompt、生成文案与提问文本均纳入审核，命中落 `flagged` |
| M12 配额 | 图像按「张数 / 月」独立计量，套餐差异化权益、`X-Quota-Remaining` 响应头与升级引导 |

### 1.3 不在本阶段（Out of Scope）

| 项 | 原因与后续安排 |
| --- | --- |
| 图像**局部重绘**（inpainting） | 需要 mask 蒙版编辑器（画笔 / 橡皮 / 撤销）与区域坐标协议，前端交互复杂度接近一个独立模块，建议单独立项 |
| 视频生成 | 属 P4 阶段 |
| 知识库图文检索（M2） | 需先落地向量库与切片策略，独立立项 |
| 成本管理看板（M10） | 依赖多模态计量数据积累，独立立项 |
| 语音（STT / TTS / Realtime） | 属 P3 阶段 |

> 说明：产品设计文档 7.2 节将「局部重绘与变体」列为同一条交付物，本阶段完成**变体重绘**，局部重绘按上表理由延后。

## 三、页面原型

### 3.1 AI 绘图工作台（核心页 · M5）

桌面端为「左参数面板 + 右结果区」，移动端上下堆叠。

```
┌────┬──────────────────────┬────────────────────────────────┐
│导航 │ 🎨 AI 绘图     [mock] │ 正在生成…      [🖼️ 我的作品(12)] │
│💬  │ 用文字描述画面…        │────────────────────────────────│
│✨  │──────────────────────│ ┌──────────┐ ┌──────────┐      │
│🎨✓ │ 画面描述     0/2000   │ │          │ │  ▓▓▓▓▓▓  │      │
│🎭  │ ┌──────────────────┐ │ │   出图   │ │  绘制中… │      │
│👑  │ │一只戴宇航头盔的青蛙│ │ │          │ │  (骨架)  │      │
│⚙️  │ └──────────────────┘ │ └──────────┘ └──────────┘      │
│    │ [灵感1][灵感2][灵感3] │  悬浮操作：⬇下载 🔄变体 🗑删除    │
│    │ 画面风格              │                                │
│    │ [▨][▨][▨][▨]         │                                │
│    │ [▨][▨][▨][🔒]        │                                │
│    │ 画面比例              │                                │
│    │ [方形][竖版][横版]     │                                │
│    │ 生图模型              │                                │
│    │ ○ Image 2 Mini ¥0.08 │                                │
│    │ ○ Image 2   🔒升级解锁│                                │
│    │ 生成张数              │                                │
│    │ [1][2🔒][3🔒][4🔒]    │                                │
│    │ [ ✨ 生成图片 ][重置]  │                                │
│    │ 本月额度 ███░░ 8/20张 │                                │
└────┴──────────────────────┴────────────────────────────────┘
```

**关键组件与交互**：
- **画面描述**：多行输入，字数计数，`Ctrl/⌘ + Enter` 快速生成；提供 4 条灵感提示词一键填充。
- **风格选择器**：8 种风格以渐变色卡呈现（智能 / 写实摄影 / 插画 / 扁平矢量 / 动漫 / 水彩 / 3D 渲染 / 国风水墨）；套餐不可用的显示 🔒，点击跳转定价页。
- **比例**：方形 1:1、竖版 2:3、横版 3:2；**结果区骨架屏按所选比例占位**，出图时无布局跳动。
- **模型 / 张数**：受套餐限制，锁定项统一引导升级。
- **结果区**：SSE 逐张上屏（已完成的图替换一个骨架位）；生成中按钮变为「⏹ 停止生成」。
- **额度条**：实时反映本月已用张数；剩余 ≤3 张时出现升级提示。
- **空状态**：展示引导文案 + 最近 8 张作品缩略图。

## 四、关键交互流程

### 4.1 文生图（核心）

```
用户填写描述 + 选择风格/比例/模型/张数
  → 前端 POST /images/generations (stream=true, SSE)
  → 后端：① 套餐权益校验（模型/风格/批量数）→ 不通过 403
          ② 图像张数配额校验 → 超额 429 + details.quota
          ③ prompt 输入审核 → 命中返回 error(content_flagged)
          ④ 拼接风格提示词 → 调 Images API（或 mock 生成占位图）
  → SSE: image.start（总张数）
        → image.item ×N（每张落盘 + 落库后立即下发，前端替换骨架位）
        → image.done（含最新配额快照）
  → 后端：落 media_assets + 落 usage_records(feature=image)
用户可中途「停止生成」→ 前端 AbortController 中断 SSE
```

**SSE 事件类型**：
- `image.start`：`{ count, model, size, style, mock }`
- `image.item`：单张资产完整 DTO（含 url / 尺寸 / prompt）
- `image.done`：`{ count, images, usage, quota }`
- `error`：`{ code, message, details }`

### 4.2 变体重绘

```
在结果区或画廊点「🔄 生成变体」
  → POST /images/:id/variations
  → 后端读取源图二进制 → 调 Images Edit API（mock 则派生占位图）
  → 复用 4.1 的 SSE 事件结构 → 新图标记 source=variation 并记录 source_id（形成重绘链）
免费版无此权益 → 前端不渲染入口，后端兜底返回 403
```

### 4.3 图像理解（看图问答）

```
对话输入框上传图片
  → POST /images/uploads (multipart/form-data)
  → 校验类型(PNG/JPEG/WebP/GIF)与体积(≤10MB) → 落盘 → 返回资产 url
用户输入问题并发送
  → POST /images/analyses { image_urls, question, conversation_id, stream }
  → 后端：① 权益校验(vision) → ② Token 配额校验 → ③ 会话归属校验
        → ④ 提问审核 → ⑤ 用户消息落库（含 attachments，先落库保证不丢）
        → ⑥ 调 Responses API（多模态 input_image）流式
  → SSE: message.start → message.delta ×N → message.done
  → 输出审核（命中则替换文案并标记 flagged）
  → AI 回复落库 + 会话标题/时间更新 + 计量（feature=vision，图片按 ~1000 token/张折算）
```

> 说明：SSE 事件复用 P1 对话的 `message.*` 结构，因此前端可与文本对话共用同一套流式处理器。
> 由于消息在生成结束后才落库，真实 `message_id` 通过 `message.done` 回传，前端据此替换临时 id。

### 4.4 图 → 文案（M5 × M3 联动）

```
选择参考图（上传或从画廊勾选，≤4 张）+ 选择用途与语气 + 填写补充要求
  → POST /images/captions
  → 后端：① 权益校验(vision) → ② Token 配额校验 → ③ 补充要求审核
        → ④ 预建 Creation 记录（立即回传 creation_id）
        → ⑤ 按「用途 + 语气」拼装 systemPrompt 约束体裁
        → ⑥ 复用 Vision 流式能力生成文案
  → SSE: message.start → message.delta ×N → message.done
  → 输出审核 → 回填 Creation.output 与成本 → 计量（feature=vision）
结果可在创作工作室「我的创作」中回看（template_id = image-caption）
```

**设计取舍**：图 → 文案本质是"以图为输入的创作"，因此**复用 M5 的 Vision 能力 + M3 的创作历史**，而非新建独立的历史表。这样用户在一个地方就能看到所有创作产出（文本模板创作 + 图生文案），也避免了重复实现列表 / 删除 / 详情等 CRUD。

### 4.5 配额与升级联动

```
生成前校验：已用 + 本次请求张数 > 月度额度 → 429 rate_limited
  → 前端在结果区展示琥珀色提示条 + 「升级套餐」按钮 → /app/pricing
锁定的模型 / 风格 / 批量数 → 前端直接显示 🔒 并跳转定价页（不发请求）
额度剩余 ≤3 张 → 参数面板额度条下方主动提示升级
响应头 X-Quota-Remaining → 每次图像请求都回传剩余张数，前端可即时预警
```

## 五、接口设计

沿用 P1 通用约定：Base URL `/api/v1`，成功 `{ data }`、失败 `{ error: { code, message, details } }`，鉴权 `Authorization: Bearer <access_token>`。

### 5.1 接口一览

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/images/options` | 生图参数目录（模型/尺寸/风格）+ 当前套餐权益与余量 |
| POST | `/images/generations` | 文生图（支持 SSE 流式，逐张下发） |
| GET | `/images` | 我的作品（分页，`?source=` 筛选） |
| GET | `/images/:id` | 单张详情 |
| DELETE | `/images/:id` | 删除（同时清理磁盘文件） |
| POST | `/images/:id/variations` | 变体重绘 |
| POST | `/images/uploads` | 上传图片（multipart/form-data） |
| POST | `/images/analyses` | 图像理解 · 看图问答（SSE 文本流，可落库到会话） |
| GET | `/images/caption-options` | 图 → 文案的用途与语气目录 |
| POST | `/images/captions` | 图 → 文案（SSE 文本流，结果存入创作历史） |
| GET | `/usage` | 用量（P1 已有，本阶段新增 `images` 字段） |

静态资源：`GET /uploads/:filename` 由后端静态托管（前端经 Next rewrite 同源代理，`<img src="/uploads/xxx.png">` 直接可用）。

**响应头**：图像相关接口在响应头返回 `X-Quota-Remaining`（剩余可生成张数，不限量时为 `unlimited`），与 P1 约定一致，便于前端在不额外请求 `/usage` 的情况下预警。

### 5.2 GET /images/options

```json
{ "data": {
  "models": [
```

## 六、数据模型

新增 `MediaAsset`，并对 P1 模型做增量扩展：

```
MediaAsset      id, user_id, type(image|video), source(generation|variation|upload),
                url, prompt, revised_prompt, model, size, style,
                width, height, bytes, mime_type,
                source_id(变体链，自引用), flagged, cost, created_at

Message         + attachments(json|null)   // 多模态输入：图片 URL 数组
UsageFeature    + image, vision            // 枚举扩展
```

**关系**：User 1—N MediaAsset；MediaAsset 1—N MediaAsset（`source_id` 自引用，构成变体重绘链）。

**与产品设计文档的差异说明**：产品文档 8.2 节将 MediaAsset 定义为 `id、user_id、type、url、prompt、meta、created_at`，即把生成参数统一塞进 `meta` JSON。本实现**把 `meta` 展开为具体列**（`model / size / style / width / height / bytes / mime_type / cost / flagged`），理由：

1. **画廊需要按风格筛选**，JSON 字段无法建索引，数据量增长后筛选会全表扫描；
2. **前端需要真实宽高**来按比例占位（避免瀑布流抖动），高频读取的字段不宜藏在 JSON 里；
3. **成本与审核标记需参与聚合统计**（用量页、审核台），列式存储才能直接 `SUM` / `WHERE`；
4. 类型安全：Prisma 能为具体列生成类型，JSON 需要手工断言，易出错。

如后续需要存放非结构化的模型私有字段（如上游返回的 seed、safety 元信息），再补一个 `meta Json?` 列承载即可，与当前设计不冲突。

**迁移**：`prisma/sql/add_media_assets.sql` 提供幂等 SQL（枚举扩展 + 建表 + 索引 + 外键 + `messages.attachments`），便于不便执行 `prisma migrate` 的环境。

**存储策略**：数据库只存 `url` 引用，文件本体落在 `MEDIA_ROOT`（默认 `uploads/`）由后端静态托管；`StorageService` 已抽象 `save / saveBase64 / saveFromUrl / remove / toAbsoluteUrl`，生产可平滑替换为 S3 兼容对象存储而不改动业务代码。

## 七、会员权益与配额

图像额度按 **张数 / 月** 独立计量，与 Token 额度并列（互不挤占）。配置集中在 `packages/shared`（`PLAN_IMAGE_LIMITS`），前后端唯一事实来源。

| 套餐 | 每月绘图 | 单次批量 | 可用模型 | 画面风格 | 看图问答 / 变体 / 图生文案 |
| --- | --- | --- | --- | --- | --- |
| 免费版 Free | 20 张 | 1 张 | Image 2 Mini | 基础 4 种 | ✗ |
| **Plus 专业版** | 500 张 | 4 张 | 全部 | 全部 8 种 | ✓ |
| Pro 旗舰版 | 5000 张 | 4 张 | 全部 | 全部 8 种 | ✓ |
| 团队版 Team | 2000 张（团队共享） | 4 张 | 全部 | 全部 8 种 | ✓ |
| 企业版 Enterprise | 不限量 | 定制 | 全部 + 专属容量 | 全部 + 定制 | ✓ |

**强制点（后端为准，前端仅做体验优化）**：
- 模型白名单 / 风格白名单 / 单次批量上限 → 违规返回 **403 forbidden**。
- 月度张数额度 → 超额返回 **429 rate_limited** 并携带 `details.quota`。
- 看图问答、变体重绘、图生文案 → 免费版返回 **403**，前端同步隐藏入口并显示 🔒 升级引导。
- 图生文案与看图问答消耗 **Token 额度**（按 ~1000 token/张折算图片），不额外扣减绘图张数。

**成本计价**（示意值，用于用量展示）：Image 2 ¥0.32/张、Image 2 Mini ¥0.08/张。

## 八、双模运行（真实 / mock）

与 P1 的 `AiService` 保持一致的双模设计，保证**本地零配置即可跑通全链路**：

| 能力 | 配置 `OPENAI_API_KEY` | 未配置（mock） |
| --- | --- | --- |
| 文生图 | Images API（`OPENAI_IMAGE_MODEL`，默认 `gpt-image-1`） | 按 prompt 哈希生成**确定性渐变 SVG 占位图**，图中标注描述摘要 / 尺寸 / 风格 |
| 变体重绘 | Images Edit API | 基于源 prompt 派生不同配色的占位图 |
| 图像理解 | Responses API（`input_image` 多模态输入） | 结构化的模拟解读文本，逐字流式输出 |
| 图 → 文案 | Responses API（`input_image` + systemPrompt 约束体裁） | 按用途返回对应体裁的**示例文案**（小红书带标签 / 电商带卖点清单 / alt text 客观描述），而非画面解读 |
| 审核 | OpenAI Moderation | 本地关键词回退 |

mock 模式下前端会在标题旁显示 `mock` 徽标（hover 说明原因），避免误判为真实模型效果。

**相关环境变量**：

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `OPENAI_API_KEY` | 空 | 未配置则图像能力进入 mock 模式 |
| `OPENAI_IMAGE_MODEL` | `gpt-image-1` | 真实生图模型 |
| `OPENAI_VISION_MODEL` | `gpt-4o-mini` | 图像理解模型 |
| `MEDIA_ROOT` | `uploads` | 媒体文件磁盘根目录 |
| `MEDIA_PUBLIC_BASE_URL` | 空 | 配置后返回绝对 URL（供上游模型访问图片时使用） |

> 注意：真实模式下做图像理解时，图片需能被 OpenAI 访问。本地开发建议配置 `MEDIA_PUBLIC_BASE_URL` 指向可公网访问地址，或改为传 data URI。
